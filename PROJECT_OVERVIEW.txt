TRUE EATS - PROJECT OVERVIEW
============================

This document describes the application as implemented in this repository. It is
intended as a practical orientation guide for developers and maintainers. It does
not include secret values from environment files, and implementation details may
change as the application evolves.


1. WHAT THE PROJECT IS
----------------------

True Eats is a full-stack food ordering website. Customers can browse a menu,
choose product options, create an account, place and track orders, pay online or
use cash on delivery (when enabled), review products, and contact customer
support. An administrator area manages products, orders, customers, payments,
promotions, reviews, support requests, and incoming contact messages.

The repository has two separately installed applications:

- frontend/: React single-page application built and served with Vite.
- backend/: Express REST API using MongoDB through Mongoose.

The root README currently links to a deployed test website and does not provide
setup instructions. The frontend package metadata has a GitHub Pages homepage,
while the README points to a Render-hosted test site. Confirm the intended
deployment target before changing deployment configuration.


2. TECHNOLOGY
-------------

Frontend:
- React 19, React DOM, React Router 7
- Vite 8 and the React Vite plugin
- Axios for API requests
- Lucide React icons
- ESLint 9

Backend:
- Node.js with CommonJS modules
- Express 5, CORS, and dotenv
- MongoDB and Mongoose
- bcryptjs and jsonwebtoken for credentials and authentication

- Nodemailer configured for Gmail SMTP

- mongodb-memory-server for local in-memory database fallback

4. HOW THE APP IS WIRED
-----------------------

The frontend entry point wraps App in AuthProvider and CartProvider. App uses
React Router and mounts ChatBot across routes. Customer-facing pages generally
render inside CustomerLayout, which supplies the customer navigation and footer.

The Axios instance uses VITE_API_URL when configured. Otherwise it points local
browser development at http://localhost:5000/api and uses a Render test API URL
for non-local hosts. When userInfo exists in localStorage, the Axios interceptor
adds its JWT as an Authorization: Bearer header.

The backend loads dotenv, starts a database connection, enables CORS, serves
backend/uploads at /uploads, accepts JSON and URL-encoded request bodies, and
mounts the API routers under /api. Its root endpoint returns a simple API-running
message. The default port is 5000 unless PORT is set.

Authentication is enforced on the API with protect middleware, which verifies a
JWT and loads the current user. The admin middleware additionally checks the
user's role. Frontend route guards provide navigation behavior but are not a
substitute for backend authorization.


5. CUSTOMER PAGES AND WORKFLOWS
-------------------------------

Public/customer routes declared in frontend/src/App.jsx:
- /                         Home and product discovery
- /product/:id              Product detail and ordering options
- /our-story                Story/about content
- /contact                  Public contact form
- /verify/:token            Email verification
- /profile                  Signed-in user's profile
- /cart                     Cart contents
- /checkout                 Signed-in checkout
- /payment-success          Signed-in payment result
- /orders                   Signed-in order history
- /support                  Signed-in customer support

Authentication routes:
- /login
- /signup
- /forgot-password
- /reset-password/:token

The cart is stored in localStorage under trueEatsCart and survives page reloads
in that browser. Cart items can represent product weight variants. Authentication
state is restored from localStorage under userInfo. Logging out removes that
stored profile. The browser should not be treated as the authoritative source of
prices, roles, or order state.

Checkout collects a shipping address, reads ordering settings and user discount,
validates coupons, and supports Online and COD methods. Online payment loads the
Razorpay Checkout.js script and asks the backend to create/verify payment orders.
The backend recalculates important order values using database products/settings.

7. BACKEND API AREAS
--------------------

All API routes are mounted beneath /api:

- /auth: signup, email verification, login, profile read/update, password
  recovery and password reset.
- /admin: customer/admin account listing and management, including role changes
  and hidden-admin state.
- /products: public menu reads and admin product create/update/delete. Product
  images may be URLs or uploaded files.
- /orders: customer order creation/history/cancellation, Razorpay order creation,
  failed payment recording, order lookup, and admin status/delivery/payment
  management and revenue statistics.
- /settings: global ordering/pricing configuration, coupons, user discounts,
  and administrator email actions.
- /reviews: product reviews, customer submissions, and admin moderation.
- /support: customer support tickets/messages and admin replies/closure.
- /contact: public contact submissions and administrator inbox/actions.

The active settings router is backend/routes/settingRoutes.js. A similarly named
settingRotes.js file also exists but is not the router imported by server.js.


8. DATA MODEL
-------------

Mongoose models in backend/models:
- User: account identity, credentials, verification/reset state, role, profile.
- Product: name, slug, description, base price, category, images, availability,
  hidden flag, ingredients, shelf life, instructions, and weight/price options.
- Order: customer, line items, shipping address, totals and discounts, sequential
  order ID, lifecycle status, payment details, and delivery/tracking details.
- Counter: supports sequential order ID generation.
- Review: customer/product review data and attached images.
- SupportTicket: customer support ticket and message history.
- Contact: incoming contact form messages and admin follow-up state.
- Settings: one global document for fees, taxes, ordering/COD flags, discounts,
  coupons, restricted users, and announcements.


9. CONFIGURATION AND LOCAL DEVELOPMENT
---------------------------------------

Prerequisites: a supported Node.js/npm installation. A persistent MongoDB
instance is recommended for data that must survive server restarts. Without
MONGO_URI, the backend attempts to use a temporary in-memory MongoDB; data in
that fallback is not durable.

Install dependencies separately because there is no root package.json:

  cd backend
  npm install
  npm run dev

In a second terminal:

  cd frontend
  npm install
  npm run dev

Vite prints the local frontend URL (normally http://localhost:5173). The backend
defaults to http://localhost:5000. Set VITE_API_URL in the frontend environment
if the API is hosted elsewhere; use the API base URL including /api.

Environment variable names referenced by the source:
- MONGO_URI: MongoDB connection string. If omitted, memory database is attempted.
- PORT: backend listening port; defaults to 5000.
- JWT_SECRET: secret used to sign and verify authentication tokens.
- FRONTEND_URL: frontend origin used when building verification/reset links.
- EMAIL_USER and EMAIL_PASS: Gmail SMTP credentials used by Nodemailer.
- RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET: server-side Razorpay credentials.
- VITE_API_URL: frontend API base URL, including /api.

The backend also has code paths that accept VITE_RAZORPAY_KEY_ID and
VITE_RAZORPAY_KEY_SECRET as fallback names; payment secrets should be kept on
the server and should never be exposed through Vite client variables.

Do not commit .env files or put real credentials in this document. Email sends
are skipped when EMAIL_USER/EMAIL_PASS are absent. Uploaded images are kept on
the backend filesystem, so deployments with ephemeral storage need persistent
storage or an external object-storage solution.

11. ITEMS TO VERIFY BEFORE PRODUCTION
-------------------------------------

- The README's live site URL is https://true-eats-test1.onrender.com/, while the
  frontend Axios fallback API currently targets
  https://true-eats-test.onrender.com/api. Check whether these are intentional
  separate deployments or a stale API URL.
- GET /api/products is public, and the controller's all=true query returns every
  product without checking admin authorization. The default query filters by
  availability but does not filter isHidden. Confirm the desired public catalog
  visibility and protect administrative listing behavior.
- GET /api/settings is public and returns the settings document. That schema
  includes hidden coupons and restricted-user data. Return only public settings
  to unauthenticated clients, and keep admin-only settings private.
- The product/cart UI supports weight-specific prices, while order normalization
  in the backend currently resolves product base price. Verify variant pricing
  end-to-end before taking real orders.
- The chatbot contains static claims about COD, but the backend settings enable
  and control COD. Keep its answers aligned with current configuration.
- CORS is enabled without an origin allowlist in server.js. Decide and configure
  allowed origins for a production deployment.
- Confirm that the Razorpay keys, MongoDB URI, JWT secret, SMTP credentials,
  FRONTEND_URL, and VITE_API_URL match the chosen deployment environments.
- Confirm persistence and backups for MongoDB and uploaded files.
- Add automated tests for authentication boundaries, pricing/coupons, variant
  orders, payment verification, and admin-only mutations.

13. WEBSITE GUIDE: FUNCTIONS AND OPTIONS
----------------------------------------

This section describes the visible website as a visitor or signed-in user would
use it. Some options depend on products, settings, account role, or order state.

VISITOR NAVIGATION

- The True Eats logo returns to the home page.
- Menu jumps to the product section on the home page.
- Our Story opens the story page.
- The search box matches product names and categories and shows up to five
  suggestions. Selecting a result opens that product.
- The cart icon opens a side drawer and shows the number of units in the cart.
- On smaller screens, navigation is in a menu overlay and product search appears
  in its own row.
- Visitors can browse the menu, product details, story, and contact form. Login
  is required for checkout, order history, profile, and support tickets.

HOME AND MENU

- The home page has an automatically rotating promotional banner. Previous/next
  arrows and slide dots allow manual selection; Shop Now scrolls to the menu.
- Active announcements appear above the banner when configured by an admin.
- Menu category buttons filter the visible products; All clears the category
  filter. Product search also matches the name, description, and category.
- Product cards open the product page or a quick-options dialog. Where available,
  the dialog lets a customer choose a weight/size, set quantity, move through
  product images, add to cart, buy now, or open full product details.
- The page also contains brand/story content and displayed statistics/perks.
  Some statistics and marketing statements are static frontend content rather
  than live calculations.

PRODUCT DETAILS

- Browse product images with previous/next controls and thumbnails; selecting
  the main image opens a larger image viewer.
- Choose an available weight/size and quantity, then Add to Cart or Buy It Now.
  Unavailable products show a sold-out state instead of purchase actions.
- Expand Ingredients, Shelf Life, or Instructions when those product details
  exist.
- Review the average rating, rating breakdown, and customer review list.
- Signed-in eligible customers can submit a star rating, optional title and
  written review, and attach review photos. Review eligibility is ultimately
  checked by the backend.
- The share action copies the product page URL where browser clipboard access is
  available.

CART AND OFFERS

- The cart drawer and full cart page show selected products, chosen weight where
  present, unit price, and quantity controls. Customers can increase/decrease
  quantities or remove a line item.
- The drawer can show a free-delivery progress indicator, public coupon choices,
  coupon code entry, and suggested products that can be added to the cart.
- The full cart page provides a cost summary, coupon application/removal, and a
  route to checkout. Ordering can be blocked by the configured minimum order or
  when ordering is disabled.
- Coupon discounts may be percentage-based or flat and can have a minimum-order
  condition. Coupon validation at checkout is handled by the API.
- Cart contents are kept in browser local storage for that browser/device.

CHECKOUT AND PAYMENT

- Checkout displays account name/email and asks for a phone number plus delivery
  details: first name, last name, address/colony, optional apartment/suite, city,
  state, and PIN code. Country/region is shown as India.
- A saved profile address or details from previous orders may prefill fields.
- Customers can change quantities, add/edit an optional note for the order, and
  apply or remove a discount code.
- The summary can include subtotal, delivery fee, platform fee, GST, coupon and
  account discounts, and total. Delivery and discount behavior depends on current
  settings and eligibility.
- Choose Pay Online (UPI, cards, net banking through Razorpay) or Cash on Delivery
  when COD is enabled. Disabled COD is displayed as unavailable.
- A phone number, address/colony, city, and PIN code are required before placing
  the order. Online payment can finish as success or failure; the result screen
  links to orders, support, shopping, or retry depending on outcome.

ACCOUNT AND ORDERS

- Signup collects first/last name, email, phone, and password. Login uses email
  and password. Password visibility can be toggled on the forms.
- Forgot Password requests a reset link by email; Reset Password accepts and
  confirms a replacement password. Signup also requires email verification.
- My Profile lets the signed-in customer update name, phone, alternate phone,
  and delivery address. Email is displayed but cannot be edited there. The page
  also offers logout, and admin users see a dashboard link.
- My Orders can be filtered by All Orders, Active, Shipped, Delivered,
  Failed/Pending, or Cancelled. The list shows order/payment status, items,
  totals, and available delivery details.
- Eligible orders can be cancelled after a confirmation prompt. Shipped,
  delivered, and already-cancelled orders are not offered cancellation. Pending
  payments may show a retry action.
- There is no customer order-detail route currently declared in the frontend;
  the detailed order page in this codebase is an admin page.

CONTACT, SUPPORT, AND CHAT

- Contact Us is a public form for name, email, optional subject, and message.
  Successful submission displays a confirmation. The page also points users to
  the support option.
- Signed-in customers can create support tickets under Order Issue, Delivery
  Help, Payment Problem, Account Support, or General Help. Order-related topics
  require choosing an order.
- Customers can attach up to four images, use suggested messages, select a
  ticket, read/reply to an open ticket, and create a new ticket after one closes.
- The site chatbot presents FAQ suggestions and keyword-based answers, can show
  product cards, and includes shortcuts to orders/contact. It also has mute,
  clear, minimize, and close controls. Its current answers are local frontend
  content, not a live AI/chat service.

ADMIN WORKSPACE

- Dashboard: view summary metrics, recent orders, and a seven-day revenue chart;
  navigate to admin modules, return to the storefront, switch theme, or log out.
- Permissions: list users, change Customer/Admin role, and delete a user after
  confirmation.
- Menu Manager: add/edit products, descriptions, ingredients, shelf life,
  instructions, categories, base and weight-specific prices, image URLs/uploads;
  change availability/visibility or delete a product.
- Live Orders: filter Kitchen Flow, Payment Pending, or All Orders; confirm
  pending online payments; advance Placed to Processing and Processing to
  Preparing; open dispatch actions or cancel where allowed. The screen refreshes
  order data periodically.
- Revenue Report: choose today/week/month/year or a custom date range; inspect
  revenue and order metrics and transactions; enter cost/selling values for an
  estimated margin; print a bill.
- Delivery Info: search an order, inspect preparing/shipped/delivered orders,
  enter tracking information and a note, dispatch or send an update, and mark a
  shipped order delivered.
- Bill Generator: create printable order bills, select/filter and bulk-print
  order bills, or compose a custom bill with customer/address/note, menu items,
  quantities, and delivery fee. The custom-bill screen is a print workflow; it
  does not appear to create an order.
- Customer Search/Profile: find customers represented in order records, inspect
  customer and order history, print invoices, open orders, send an email, or
  send a selected coupon with an optional message.
- Order Detail: inspect customer, address, note, items, totals, and payment;
  cancel eligible orders or send an email update, optionally with tracking ID
  and courier name.
- System Settings: adjust delivery/minimum-order/platform fees, GST, free
  delivery, ordering and COD switches, first-order discount, coupons, product
  availability, restricted users, and homepage announcements. Changes can be
  saved by section or with Save All Changes.
- Payment Ledger: review payment totals and counts, filter/search statuses,
  inspect transaction details, refresh, and manually confirm pending online
  payments. Payment Detail offers transaction/shipping information and printing.
- Reviews: inspect summary/rating counts, filter by star rating, search review
  content/customer/product, and delete reviews after confirmation.
- Support Inbox: filter/search tickets, read conversations, reply with text and
  up to four images, close tickets, and refresh.
- Reach Out: search/filter contact submissions, read a message, send or resend a
  reply, mark it replied/resolved, or delete it.

SITE ELEMENTS THAT ARE NOT FULLY WIRED

- Footer social links point to #, and Privacy Policy, Terms of Service, and
  Refund Policy appear as text rather than working destination links.
- Some home-page statistics/perks are fixed display content, not computed from
  current database data.
- Admin screen controls can depend on account role and current order status;
  available actions change as the order moves through its lifecycle.
